# Onpreo-Agent-Pro-POC

A self-contained POC pairing an **MCP server** with a **Streamlit UI**, backed by a
local SQLite database (SQLModel + Alembic). The MCP server exposes one tool,
`onpreo_create_call_activity`, over **Streamable HTTP** (intended to be tunneled via
ngrok) and protected by a static bearer token.

When a call activity includes a caller name, a `Contact` is upserted (de-duplicated on
a trimmed/lowercased name) and the activity is linked to it — mirroring CRM enrichment.

## Stack

- **uv** — environment & dependency management
- **mcp** (`FastMCP`, stateless Streamable HTTP)
- **SQLModel** + **Alembic** (SQLite)
- **Streamlit** — read-only viewer
- **pydantic-settings** — typed `.env` config

## Setup

```bash
uv sync                       # create .venv and install deps
cp .env.example .env          # then set MCP_BEARER_TOKEN
uv run alembic upgrade head   # create onpreo_poc.db with both tables
```

`.env`:

```
MCP_BEARER_TOKEN=your-secret-token
# DATABASE_URL=sqlite:///./onpreo_poc.db   # optional override
```

The server refuses to start if `MCP_BEARER_TOKEN` is unset (fail closed).

> The committed `onpreo_poc.db` may contain a few example rows from end-to-end testing.
> For a clean slate: `del onpreo_poc.db` (PowerShell) then `uv run alembic upgrade head`.

## Run the MCP server

```bash
uv run python -m app.mcp_server
```

Serves `http://127.0.0.1:8000/mcp`. Every request must carry
`Authorization: Bearer <MCP_BEARER_TOKEN>`.

Expose it for an external MCP client:

```bash
ngrok http 8000
# connect the client to https://<ngrok-id>.ngrok-free.app/mcp with the bearer header
```

## Run the UI

```bash
uv run streamlit run app/streamlit_app.py
```

Shows the stored call activities and contacts; use **Refresh** after new tool calls.

## The tool

`onpreo_create_call_activity(title, description, caller_first_name, caller_last_name)` —
all four parameters are required and nullable (`["string", "null"]`). Returns
`{activity_id, contact_id}` (`contact_id` is null when no name was provided). Rows are
persisted to SQLite and shown in the Streamlit UI.

## Database migrations

Schema lives in `app/models.py`. After changing it:

```bash
uv run alembic revision --autogenerate -m "describe change"
uv run alembic upgrade head
```

> Note: `alembic/script.py.mako` imports `sqlmodel` so autogenerated migrations using
> `sqlmodel.sql.sqltypes.*` apply without a `NameError`.

## Project layout

```
app/
  config.py        # pydantic-settings (.env)
  db.py            # engine, session, SQLite WAL
  models.py        # Contact, CallActivity
  crud.py          # upsert_contact, create_call_activity
  mcp_server.py    # FastMCP tool + bearer-auth ASGI wrapper
  streamlit_app.py # viewer
alembic/           # migrations
```
